# COVER STATUS BUSINESS HARDENING REPORT

**Programme :** Cover Engine — Business State Hardening v1.1  
**Date :** 4 juillet 2026  
**Domaine :** Publication & Catalogue — Artwork Runtime  
**Statut :** **COVER STATUS BUSINESS HARDENED v1.1**

---

## 1. Objectif de la mission

Renforcer l'architecture métier du Cover Engine **sans modifier le comportement UX v1.0**.  
Ajouter un état métier persistant `cover_status` distinct de l'origine technique `cover_source`, pour tracer l'historique business (pochette auto vs remplacée par l'artiste) et piloter le badge catalogue.

---

## 2. Architecture avant

| Champ | Stockage | Rôle |
|---|---|---|
| `cover_path` | `albums.cover_path` | Chemin storage |
| `cover_source` | `albums.metadata.cover_source` | Origine technique : `user` \| `auto` |
| Badge catalogue | `isAutoGeneratedCover()` basé sur `cover_source === "auto"` | Pas d'état métier dédié |

**Limite :** impossible de distinguer « image utilisateur dès la création » vs « remplacement après pochette auto » — même valeur `cover_source=user`.

---

## 3. Architecture après

| Champ | Stockage | Rôle |
|---|---|---|
| `cover_path` | `albums.cover_path` | Chemin storage (inchangé) |
| `cover_source` | `albums.metadata.cover_source` | Origine technique (conservé) |
| `cover_status` | `albums.cover_status` (colonne DB) | État métier : `AUTO_GENERATED` \| `USER_REPLACED` |
| Badge catalogue | `isAutoGeneratedCover()` → `cover_status === AUTO_GENERATED` | Badge discret conditionnel |

**Service central :** `applyCoverArtworkState(source)` — met à jour `cover_source` + `cover_status` atomiquement via `patchAlbumCoverArtworkState()`.

---

## 4. Machine d'état métier

```
                    ┌─────────────────────┐
                    │   AUTO_GENERATED    │  ← défaut à la création
                    └──────────┬──────────┘
                               │
              pochette auto (Cas 2/3/4)
              ou état initial sans cover
                               │
              remplacement artiste (Cas 5)
              ou image user dès le départ (Cas 1)
                               ▼
                    ┌─────────────────────┐
                    │   USER_REPLACED     │  ← état terminal MVP
                    └─────────────────────┘
```

Pas de retour `USER_REPLACED → AUTO_GENERATED` en v1.1 (hors scope MVP).

---

## 5. Mapping cover_source / cover_status

| Scénario | cover_source | cover_status |
|---|---|---|
| Cas 1 — Image conforme dès création | `user` | `USER_REPLACED` |
| Cas 2 — Aucune image → auto | `auto` | `AUTO_GENERATED` |
| Cas 3 — Image trop petite → auto | `auto` | `AUTO_GENERATED` |
| Cas 4 — Image corrompue → auto | `auto` | `AUTO_GENERATED` |
| Cas 5 — Remplacement ultérieur | `user` | `USER_REPLACED` |

Fonction : `coverStatusFromSource()` — `auto → AUTO_GENERATED`, `user → USER_REPLACED`.

---

## 6. Migration appliquée

**Fichier :** `supabase/migrations/20260704120000_albums_cover_status.sql`

- Colonne `albums.cover_status TEXT NOT NULL DEFAULT 'AUTO_GENERATED'`
- Contrainte `CHECK (cover_status IN ('AUTO_GENERATED', 'USER_REPLACED'))`
- Backfill :
  - `USER_REPLACED` si `metadata.cover_source = 'user'` ou pochette legacy sans flag `auto`
  - Sinon `AUTO_GENERATED`

**Production (2026-07-04) :** 46 `AUTO_GENERATED` · 34 `USER_REPLACED`
