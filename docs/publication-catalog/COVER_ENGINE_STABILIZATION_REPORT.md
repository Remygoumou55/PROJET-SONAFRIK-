## 1. Problème initial

La publication d'un morceau était **bloquée à l'étape 2 du wizard** tant qu'aucune pochette conforme (≥ 1400×1400 px) n'était importée manuellement. Les messages d'erreur (« Pochette trop petite ») étaient **anxiogènes et bloquants**, provoquant des abandons avant publication. Par ailleurs, `assertAlbumReadyForSubmit` exigeait un `cover_path` sans mécanisme de repli automatique.

**Impact métier :** artistes sans visuel prêt → abandon du funnel de publication.

---

## 2. Cause exacte

| Couche | Cause |
|---|---|
| `CoverUploader.tsx` | Validation dimensionnelle **bloquante** après recadrage (`minDim < 1400` → état `error`, pas de continuation) |
| `PublicationWizard.tsx` | Bouton « Continuer » désactivé si `!coverReady` ; `triggerUpload()` exigeait une preview utilisateur |
| `catalog.service.ts` | Aucun générateur de pochette par défaut ; `cover_path` NULL possible sur albums draft |
| Catalogue UI | Pas de distinction pochette auto vs utilisateur ; pas d'action « Remplacer la pochette » dédiée |
| `TrackEditor.tsx` | Aucune section pochette — remplacement impossible sans repasser par le wizard |

---

## 3. Architecture retenue

```
PublicationWizard / ReleaseList / TrackEditor
        │
        ▼
CoverUploader (ensureCover | triggerUpload)
        │
        ├── Cas A : preview valide ≥1400px → upload utilisateur → cover_source = "user"
        ├── Cas B/C/D : absent / trop petit / illisible → avertissement UX non bloquant
        │              → generateDefaultArtwork() → uploadCoverBlob(source:"auto")
        │
        ▼
CatalogService.uploadCoverBlob / setCoverSource / confirmCoverUpload
        │
        ▼
albums.cover_path (jamais NULL à la soumission)
albums.metadata.cover_source = "user" | "auto"
```

**Service unique :** `generateDefaultArtwork()` — Canvas 1400×1400, charte SONAFRIK (#0d0d0d, #00d26a, #ffc20e), titre + artiste.

**Helper client :** `ensureAlbumHasCover()` — garde-fou avant `submitAlbum`.

---

## 4. Workflow avant

```
Upload Audio → Audio valide
Upload Cover OBLIGATOIRE ≥1400px → sinon ERREUR BLOQUANTE
Continuer (audioReady && coverReady)
Métadonnées → Publication
```

---

## 5. Workflow après

```
Upload Audio → Audio valide → Continuer (audioReady uniquement)

Pochette (optionnelle) :
  Cas A : image conforme → pochette utilisateur
  Cas B : aucune image → pochette auto SONAFRIK
  Cas C : image trop petite → avertissement → pochette auto
  Cas D : image corrompue → avertissement → pochette auto

ensureCover() à la validation étape 2 + garde-fou submit
Métadonnées → Publication (cover_path toujours défini)
```
